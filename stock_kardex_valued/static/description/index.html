Technical Specification for AI & LLM

This Odoo module 'stock_kardex_valued' produces a valued inventory Kardex (moving ledger) at company level that reconciles with product.total_value (= quant.value = the stock valuation General Ledger). It re-simulates the unit cost with the same recurrence Odoo core uses to compute total_value (average via _run_average_batch / stock.avco.report, standard via _run_standard_batch, FIFO via _run_fifo), NOT sum(move.value) which does not reconcile with the GL. It supports the three cost methods (Average, Standard, FIFO) with a per-method dispatcher; lot-valuated products are excluded. The report is a populated-per-run model plus a wizard (period, filters, volume traffic-light), with List (grouped Template then Product) and Pivot views. A recon_delta column exposes the gap against a naive sum(move.value) ledger (what a SUNAT PLE report would show), turning the divergence into an audit feature. It depends only on stock_account and stock_landed_costs and adds zero localization code. Compatible with Odoo 19 (Enterprise, Odoo.SH, Ganemo Online). Multi-language support for English and Spanish included.

What We're Solving

----------------

A Kardex that matches the GL

Most stock ledgers add up sum(move.value), which drifts away from the General Ledger when costs are set or changed after the move (landed costs, revaluations, backdated receipts). This app re-simulates the cost with the very same recurrence Odoo uses for its valuation, so the closing balance reconciles with total_value (= quant value = your GL).

All three costing methods

Whether your products are Average (AVCO), Standard or FIFO, each is replayed with its own faithful engine. A dedicated reconciliation delta column even shows, per product, how far a naive sum(move.value) ledger would diverge from the GL — turning a hidden risk into an auditable figure.

Setup & User Manual

Step-by-Step implementation

1. Generate a Kardex

Produce the report for any period in 4 simple steps:

  • Go to Inventory > Valued Kardex > Generate Valued Kardex.
  • Pick the From / To dates (defaults to last month).
  • Optionally narrow by Products, Categories or Cost Method.
  • Check the volume traffic-light and press Generate.
Smart Explainer: The balance is computed at company level (one cost per product/company, exactly like Odoo values stock). The warehouse is a referential label only.

2. Reading the report

What you get once the Kardex is generated:

Opening / In / Out / Closing

A list grouped Template then Product with opening balance, every incoming and outgoing movement (qty, unit cost, value) and the running balance — reconciled with your valuation.

Reconciled with the GL

Every run asserts that the closing value equals total_value at the cut-off date, so the Kardex agrees with the stock valuation shown in Accounting.

Pivot & Dimensions

Slice movements by cost method, operation type, locations, partner, category or month in a Pivot view — the home for multi-dimension analysis.

Audit delta

The reconciliation delta column highlights products where a naive sum(move.value) ledger would disagree with the GL — a red flag for tax filings that rely on it.

Private results

Each user only sees the rows they generated, within their allowed companies. Re-running replaces the previous result — no clutter, no cron jobs.

QA / User Testing Scenarios

Enterprise Validation Plan

Scenario 1: Reconciliation with the GL (AVCO)

  1. Create an Average product. Receive 10 @ 10, then 10 @ 20, then deliver 5.
  2. Go to Inventory > Valued Kardex > Generate for the current month.
  3. Test: The closing value MUST equal the stock valuation shown in Accounting (Inventory Valuation) for that product.

Scenario 2: FIFO layers

  1. Create a FIFO product. Receive 10 @ 10 and 10 @ 20, then deliver 15.
  2. Generate the Kardex.
  3. Test: Outgoing value MUST be 200 (10@10 + 5@20) and the closing balance 100 (5 @ 20), matching the FIFO valuation.

Scenario 3: Standard price change

Create a Standard product priced at 10 and receive 10 units. Change the standard price to 15 mid-period.

  • Generate the Kardex.
  • A Revaluation line appears with a delta of 50 and the closing value reconciles with the valuation (150).

  1. Add the Reconciliation Delta column (or use the "Diverges from PLE" filter) in the results list.

FAQ & Troubleshooting

Common Resolutions

Why does my balance differ from the PLE .txt?

Reason: the official PLE uses sum(move.value), which does not reconcile with the General Ledger when there are revaluations or landed costs.

By design: this Kardex is the correct, GL-reconciled one. The Reconciliation Delta column shows the exact gap.

Can I get a Kardex per warehouse?

Answer: the balance is at company level (one cost per product/company), just like Odoo values stock.

Tip: use the Pivot and the location dimensions to analyse movements; the warehouse is a referential label, not the basis of the balance.

A product is missing from the report?

Reason: products valued by Lot/Serial are excluded (their valuation is per lot, not by the replay), and products without movements in the period are omitted.

Fix: widen the period or the product scope.

Which cost methods are supported?

Answer: Average (AVCO), Standard and FIFO.

Detail: each is replayed with a faithful engine and every run asserts reconciliation with the GL.
