Technical Specification for AI & LLM

This Odoo 18 module 'delivery_status_tracking' (Delivery Status Tracking - Carriers & Drivers) depends on 'stock_delivery'. It adds the model 'stock.delivery.state' (name, sequence, active, company_id, technical code selection: pending, recorded, in_transit, delivered, incident, canceled; icon as Font Awesome class; is_result_state; result_type success/partial/failure; optional mail_template_id on stock.picking) and extends 'stock.picking' with delivery_state_id, delivery_state_code, delivery_date_done, delivery_tracking_message, delivery_tracking_history, delivery_tracking_data and delivery_tracking_error. Carrier integrations implement the hook '<delivery_type>_get_delivery_state(picking)' on 'delivery.carrier' returning a dict with 'code', 'message' and 'data'; the method '_set_delivery_state(code, message, data)' applies it. A scheduled action (hourly) asks the carriers about validated transfers that are not yet delivered or cancelled and stores errors per transfer without stopping the others. When a transfer reaches a result state, the delivery date is stored. The state can also be set by hand for carriers without integration. Five states are created on install: recorded by the carrier, in transit, delivered, incident, cancelled. Multi-company aware. Simulation mode per shipping method ('delivery.carrier' fields delivery_simulation and delivery_simulation_prefix): for shipping methods without their own integration, validating a delivery to a customer generates a fictitious tracking number (prefix + 10 digits) and the recorded state; each update or scheduled run moves it to in transit and then delivered; cancelling sets cancelled without calling any carrier. Demo data: UPS Standard, GLS Business Parcel, SEUR 24 and Correos Express Paq 24 in simulation, two customers, one product and three deliveries ready to validate. Used by delivery_sendcloud_dropship (Sendcloud) and designed as a common base for the Ganemo driver portal. Compatible with Odoo 18 (Enterprise, Odoo.SH, Ganemo Online). NOT supported on Odoo Online due to custom code restrictions. English and Spanish translations included.

Delivery Status

Carriers & Drivers Tracking

Know where every delivery is: recorded, in transit, delivered or incident. Updated automatically by your carrier integrations, or set by hand for carriers without one.

What We're Solving

----------------

Delivery State on Every Transfer

Odoo knows when a transfer is validated, but not what happened to the parcel afterwards. This app adds a delivery state, a delivery date and the carrier's own status history to each transfer, so your team stops calling the carrier to ask.

States You Control

Configure your own states with a technical code (pending, recorded, in transit, delivered, incident, cancelled), an icon and a result type (success, partial or failure). Rename or translate them freely: integrations work through the code, not the name.

Carrier Integrations, Zero Effort

Carrier connectors (for example Sendcloud with delivery_sendcloud_dropship) update the state through a simple hook. A scheduled action asks the carriers every hour about the transfers still on the way.

Manual When You Need It

Working with a carrier that has no integration? Just set the Delivery State by hand on the transfer. The delivery date is stored as soon as the transfer reaches a final state.

Simulation Mode for Demos

Turn on Simulate Carrier Integration on a shipping method and show the whole flow without a real carrier: a fictitious tracking number, then recorded, in transit, delivered at every update. Perfect for demos and training, never for production.

Demo Data Ready to Try

With demo data you get UPS Standard, GLS Business Parcel, SEUR 24 and Correos Express Paq 24 in simulation, with their public tracking pages, two customers and three deliveries ready to validate.

Setup & User Manual

Step-by-Step implementation

1. Configuration Guide

Ready to use after installation. To adapt it to your operation:

  • Go to Inventory > Configuration > Delivery > Delivery States.
  • Five states are created on install: Recorded by the carrier, In transit, Delivered, Incident, Cancelled.
  • Edit a state or create a new one: name, sequence, Font Awesome icon (e.g. fa-truck).
  • Choose the Technical Code: it is what integrations use to set the state.
  • Tick Is Result State for final outcomes and pick Success, Partial Success or Failure.
  • Optionally select an Email Template: it is sent to the transfer contact when the transfer enters the state.
Multi-company: states belong to a company. If a company needs a state it does not have yet, it gets its own copy automatically the first time it is needed.
Simulation (demos and training only): in Inventory > Configuration > Delivery > Shipping Methods, tick Simulate Carrier Integration and, optionally, set the Simulated Tracking Prefix (e.g. 1Z999AA1 for UPS). A yellow notice on the form shows that simulation is on. Never enable it in production.

2. Operating Manual (Workflow)

How the system behaves for the end-user:

On the Transfer

In the Additional Info tab, under Shipping Information, you see the Delivery State, the Delivery Date, the last Carrier Status, its history and the error of the last automatic request, if any.

Automatic Updates

Sending the shipment through an integrated carrier sets Recorded; cancelling it sets Cancelled. The hourly scheduled action then asks the carrier about every validated transfer that is not yet delivered or cancelled.

Update Button

On validated transfers of integrated carriers, the Update button next to the state asks the carrier right now, without waiting for the next scheduled run.

Manual Mode

For carriers without integration, pick the state yourself. Reaching a result state such as Delivered stores the delivery date automatically.

Robust by Design

If the carrier fails for one transfer, the error is stored on that transfer and the others keep being updated. An unknown status keeps the current state and just records the message.

Simulated Carriers

For shipping methods without their own integration (fixed price or rules) in simulation, validating a delivery to a customer gives it a fictitious tracking number (prefix + 10 digits; one typed by hand is kept) and the Recorded state. Each Update or scheduled run moves it to In transit and then Delivered. Cancelling the shipment sets Cancelled without calling anyone.

Demo Data

Installed with demo data: UPS Standard (prefix 1Z999AA1), GLS Business Parcel, SEUR 24 and Correos Express Paq 24 in simulation; the customers Hotel Mirador del Port and Cafetería Plaça Nova; the product Custom printed paper cup 8 oz; and three delivery orders ready to validate.

List and Search

Add the optional Delivery State column to the transfer list and group transfers by Delivery State in the search view to see what is on the road.

3. For Carrier Integrations

Connect any carrier with a single method on delivery.carrier:

def <delivery_type>_get_delivery_state(self, picking):
    return {'code': 'in_transit', 'message': 'Picked up by driver', 'data': {...}}

The module does the rest: it applies the state, keeps the history and the delivery date. It is also a common base for the Ganemo driver portal, which uses the same model and field names.

QA / User Testing Scenarios

Enterprise Validation Plan

Scenario 1: Default States

  1. Go to Inventory > Configuration > Delivery > Delivery States.
  2. Result: Recorded, In transit, Delivered, Incident and Cancelled exist. Only Delivered is a result state (Success).

Scenario 2: Manual State and Delivery Date

  1. Open a validated delivery order whose carrier has no integration.
  2. In Additional Info > Shipping Information, set Delivery State to In transit.
  3. Change it to Delivered.
  4. Result: the Delivery Date is filled in automatically.

Scenario 3: Carrier Integration

  1. Send a shipment with an integrated carrier (e.g. Sendcloud).
  2. Result: the transfer shows Recorded by the carrier.
  3. Click Update (or wait for the hourly scheduled action).
  4. Result: the state, the carrier status and its history follow the carrier.

Scenario 4: Email Template per State

  1. Edit the Delivered state and select an Email Template.
  2. Move a transfer to Delivered.
  3. Result: the transfer contact receives the email.

Scenario 5: Cancellation and Errors

  1. Cancel the shipment of an integrated carrier: the state becomes Cancelled and it is no longer asked to the carrier.
  2. If the carrier returns an error for one transfer, the error is shown on that transfer and the other transfers are still updated.

Scenario 6: Simulated Carrier (Demo Data)

  1. Open the delivery order of Hotel Mirador del Port with UPS Standard and validate it.
  2. Result: the transfer gets a tracking number starting with 1Z999AA1 followed by 10 digits, a tracking link to the UPS page, and the state Recorded.
  3. Click Update twice.
  4. Result: the state goes to In transit and then Delivered, the Delivery Date is filled in, and a further update changes nothing.

Scenario 7: Simulation Cancel and Scheduled Action

  1. Validate two deliveries of a simulated shipping method and cancel the shipment of one.
  2. Run the scheduled action Delivery Status Tracking: ask the carriers.
  3. Result: the first one moves to In transit; the cancelled one stays Cancelled and is not asked again.

FAQ & Troubleshooting

Common Resolutions

The Update button does not appear

Reason: The button is only shown for validated transfers whose carrier integration supports delivery status.

Fix: Check that the carrier has an integration that implements the delivery state hook, and that the transfer is in Done status. For other carriers, set the state by hand.

The state does not change

Reason: The carrier returned a status the integration cannot map, or an error.

Fix: An unknown status keeps the current state and records the message under Carrier Status. Check Carrier Status Error on the transfer.

I renamed a state and the integration stopped

Reason: It should not: integrations set states through the Technical Code, not the name.

Fix: Make sure the state still has the right Technical Code selected.

Is this compatible with Multi-company?

Answer: Yes!

Detail: States belong to a company. A company that needs a state it does not have gets its own copy automatically.

The simulated shipment got no tracking number

Reason: The tracking number is generated only when a delivery to a customer is validated, on a shipping method without its own integration and with Simulate Carrier Integration on.

Fix: Check the shipping method on the transfer and that the destination is a customer location. A number typed by hand before validating is kept.

Can I use simulation in production?

Answer: No. Nothing is sent to the carrier, so real parcels would show fictitious data.

Detail: It is meant for demos and training. A yellow notice on the shipping method form warns you while it is on; untick Simulate Carrier Integration to go live.
