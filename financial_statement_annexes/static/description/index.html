Financial Statement Annexes

Stop struggling with end-of-month reconciliations. Generate audit-ready Accounts Receivable & Payable reports with precise cut-off dates and advanced aging analysis in seconds.

The Problem

Native Odoo reports often reflect the current status of a partner's debt, making it difficult to reconstruct the exact balance at a specific past date. Auditors demand historical accuracy (e.g., "What was the balance on Dec 31st?"), and manual spreadsheet reconstruction is prone to errors.

Our Solution

We augment Odoo's reporting engine to freeze time. Select any past date, and our engine recalculates the exact open balance for every partner as of that moment. combined with flexible aging buckets (1-30, 31-60 days), it's the ultimate tool for financial controllers.

Key Capabilities

Precise Cut-Off Dates

Generate reports as of any historical date. Perfect for month-end and year-end closing.

Advanced Aging

Visualize debt maturity with configurable buckets (Current, 1-30, 30-60, 60+ days) to prioritize collections.

Native Excel Export

Direct export to professionally formatted Excel files, ready for presentation to auditors or management.

How It Works

1
Access the Report

Navigate to Accounting > Reporting > Financial Reports > Notas y Anexos (Excel).

2
Set Your Parameters

Choose your Start Date and End Date. Select whether you want accurate accounts Payable or Receivable.

3
Enable Aging Analysis

Toggle the "Reporte de Antigüedad" option to break down balances by days overdue.

4
Export & Analyze

User Manual & Guide

Configuration

The module is designed for "Plug & Play" use. No complex configuration settings are required in the General Settings.

  • Prerequisites: Ensure the user has the "Show Full Accounting Features" rights or equivalent Accountant access to view the Reporting menu.
  • Access: The report menu is automatically added at Accounting > Reporting > Financial Reports > Notas y Anexos (Excel).
  • Multi-Company: The report respects the currently selected company in the Odoo environment.

Daily Workflow Guide

How to use this tool in your day-to-day operations for audits and internal controls.

1. End-of-Month Review

When closing the month (e.g., January), you need to know exactly who owed what on Jan 31st.
Action: Run the report with End Date = 01/31/YYYY. The system recalculates balances as if it were that day, ignoring payments made in February.

2. Audit Requests

External auditors often ask for a "breakdown of Accounts Payable as of Dec 31st".
Action: Select "Payable Accounts", set the date to Dec 31st, and export to Excel. The file contains partner names, VAT numbers, and detailed amounts matching the Trial Balance.

3. Collections Management

Use the Aging feature to spot overdue invoices.
Action: Enable "Reporte de Antigüedad". The Excel file will show columns like "1-30 Days", "31-60 Days", making it easy to filter and send dunning emails to the right customers.

QA / User Testing Scenarios

Follow these scenarios to verify the module's accuracy in your environment.

Scenario 1: Historical Balance Accuracy
  1. Create an Invoice for Customer A for $1000 on Jan 1st.
  2. Register a Payment of $1000 on Feb 1st.
  3. Run the report with End Date = Jan 15th.
  4. Expected Result: Customer A should show a balance of $1000 (Payment from Feb is ignored).
  5. Run the report with End Date = Feb 2nd.
  6. Expected Result: Customer A should NOT appear (or show $0 balance).
Scenario 2: Aging Buckets Verification
  1. Set report date to Today.
  2. Find an invoice that is 45 days overdue.
  3. Enable "Reporte de Antigüedad".
  4. Expected Result: The amount should appear specifically in the 31-60 Days column in the Excel file.
Scenario 3: Partial Payments
  1. Create an invoice for $1000. Pay $400. Remaining = $600.
  2. Run the report.
  3. Expected Result: The report should show the Residual Amount of $600, not the original $1000.
Scenario 4: Multi-Currency Validation (Amount Currency)
  1. Create multiple Invoices in a foreign currency (e.g., 2 invoices of $100 USD each).
  2. Run the report.
  3. Expected Result: The report should correctly display and SUM the "Amount Currency" column (showing $200 USD total), ensuring the original currency values are preserved alongside the converted amounts.
Scenario 5: Balance Sheet Accounts (Non-Reconcilable)
  1. Select an account like Equity, Fixed Assets, or Bank (if not set to reconcile).
  2. Run the report with End Date = Jan 31st.
  3. Expected Result: The report displays the Cumulative Balance (Historic) up to the End Date. It ignores the Start Date for the calculation, behaving like a true Balance Sheet.
Scenario 6: Profit & Loss Accounts
  1. Select an Income or Expense account.
  2. Run the report with Start Date = Jan 1st and End Date = Jan 31st.
  3. Expected Result: The report displays the sum of movements strictly within the Date Range (Period Activity), ignoring previous balances.

FAQ & Troubleshooting

Why is the report empty?

Double-check your Date Range and Account Type selection. If you select "Payable" but only have Customer Invoices (Receivable), the report will be empty. Also, ensure there are Posted entries in that period.

I can't see the menu item.

This usually means your user is missing permissions. Ensure you have "Accountant" or "Manager" level access in the Accounting app settings.

Does it support Multi-Currency?

Yes. The report exports values in the company's currency. Foreign currency transactions are converted using the exchange rate active at the date of the transaction (or the report date, depending on configured valuation settings).

Can I customize the aging buckets?

The current version uses standard standard 30-day buckets (1-30, 31-60, 61-90, 90+). Custom bucket configuration is available in our Enterprise+ version or via customization request.
