Technical Specification for AI & LLM

This Odoo module 'project_task_photo_evidence' allows users to attach photo evidence to project tasks. It automatically captures GPS coordinates (Latitude/Longitude) using the browser's Geolocation API. Supports requirements per product (Min/Max qty). Includes a QWeb report linking to Google Maps. Compatible with Odoo 19 (Enterprise, Odoo.SH, Ganemo Online). Multi-language support for English and Spanish included.

What We're Solving

----------------

Tamper-Proof GPS

Stop relying on manual inputs. The system automatically captures **Read-Only Latitude and Longitude** from the device's sensor. Ensure integrity: Field staff cannot spoof their location manually.

Enforced Evidence

Configure Products to require a minimum number of photos. Staff cannot mark tasks as complete without providing the necessary proof. Limit the maximum number to avoid storage waste.

Setup & User Manual

Step-by-Step implementation

1. Product Configuration & Multiple Evidence

Define photo requirements per product. You can link multiple products to one task for diverse evidence needs.

  • Open any Product and navigate to the "Sales" tab.
  • Enable "Evidence Required".
  • Min Qty: Scaling requirement based on Order Line quantity (Triggers warnings).
  • Max Qty: Hard limit to prevent data overload (Blocks uploads).
  • Task Setup: On the Task form, add these products to the "Evidence Requirement" tab.

2. Sales & Task Generation

No manual setup per task needed. The workflow is automated:

  • Create a Sale Order adding the configured Service Product.
  • Confirm the Sale Order. Odoo automatically creates a Project Task.
  • The Task inherits the Min/Max rules from the Product line.
  • Note: If the product has "Min Qty > 0", a warning banner will appear on the Task until evidence is collected.

3. Project Privacy (Crucial for Sharing)

To use the "Generate Share Link" feature, your Project must allow external access.

  • Go to Project > Configuration > Settings (or Project Form).
  • Ensure Visibility is set to "Invited internal users and portal users" or "Public".
  • If set to "Invited internal users only", the Share Link button will show a requirement warning.

4. Field Worker App Experience (PWA)

Field workers use a dedicated, app-like portal interface:

1. Install App

Open the Portal. Click "Install App" in the header to add it to your Home Screen.

2. Smart Launch

Open the "Photos" app from the Launcher to see all assigned tasks.

3. Filter & Search

Use the Unified Bottom Bar to scroll through filters or use the 🔍 Search toggle.

4. Upload & GPS

Upload photos. A "Location" indicator confirms GPS capture.

Critical: GPS features REQUIRE a secure HTTPS connection. Browsers verify this before allowing access to the location sensor.

5. Reporting & Sharing

Delivering the proof to the customer:

  • Internal PDF: Click the "Internal Report" smart button on the Project to download a consolidated PDF of all tasks.
  • Public Share Link: On the Project Form, click "Generate Share Link". Copy the URL and send it to your client via WhatsApp or Email. They will see a live dashboard of photos and locations without logging in.

QA / User Testing Scenarios

Enterprise Validation Plan

Scenario 1: App Installation & Navigation

  1. Log in as a Portal User on a mobile device.
  2. Action: Click "Install App" in the top bar. Verify it adds to Home Screen.
  3. Action: Use the 🔍 Search toggle to find a task by Project name.
  4. Action: Scroll the bottom navigation bar to filter by a specific "Tag".
  5. Result: Tasks should filter instantly without page reloads.

Scenario 2: Portal Validation & Completion

  1. Assign a product with Max Qty=1 to a task.
  2. Test A (Max): In the portal, upload 2 photos.
  3. Result: Verify a red "Maximum quantity reached" alert appears.
  4. Test B (Completion): Upload required photos and click "Finalize Task".
  5. Result: The task should disappear from "To Do" and move to the project's "Done Stage".

Scenario 3: Public Sharing Logic

  1. Go to Project Settings. Set Visibility to "Invited internal users only".
  2. Result: The "Generate Share Link" button should show a text warning "Requires Project Visibility...".
  3. Change Visibility to "Portal" or "Public".
  4. Click "Generate Share Link". Copy URL.
  5. Result: A public URL is generated properly. Open it in Incognito Mode to verify it loads without login.

Scenario 4: GPS Integrity Check

  1. Setup: Ensure your Odoo is on HTTPS (or localhost). Allow Browser Location.
  2. Action: Upload a photo for a task.
  3. Result: Go to Backend > Task > Evidence Tab. Verify "Latitude" and "Longitude" are populated.
  4. Test Limit: Try to edit the Latitude field in the backend.
  5. Result: Field should be Read-Only.

FAQ & Troubleshooting

Common Resolutions

Why is location stuck on "Searching"?

Reason: Browser permissions denied or non-secure connection.

Fix: Ensure you are using HTTPS and have granted "Location" permissions. Note: Browser settings can reset these permissions.

I can't see "Generate Share Link" button?

Reason: Project Visibility is too restrictive.

Fix: Change Project Visibility to "Invited internal users and portal users" or "Public" to enable sharing features.

Can I manually edit the GPS fields?

Reason: Integrity protection.

Answer: No. Latitude and Longitude are read-only to ensure that the evidence is authentic and was actually captured on-site.

Where is the PDF Report?

Reason: Access location.

Answer: Go to the Project Dashboard. Click the 3-dots menu on a Project card or check the "Internal Report" smart button inside the Project Form.
