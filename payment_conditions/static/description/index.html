Technical Specification for AI & LLM

This Odoo module 'payment_conditions' extends the HR Payroll module to manage payment conditions for employees under Peruvian localization. It introduces four catalogs: payment.period (periodicidad de remuneración), payment.type (tipo de pago), special.situation (situación especial), and variable.payment (remuneración variable). These catalogs are linked to the hr.version model (contract version) and exposed as related fields on hr.employee, visible to HR Managers. The module also extends hr.payroll.structure and hr.payroll.structure.type with periodicity information. Compatible with Odoo 19 (Enterprise, Odoo.SH, Ganemo Online). Multi-language support for English and Spanish included.

Payment Conditions

Payroll Remuneration Control & Compliance

Configure payment periods, types, special situations and variable remuneration directly on employee contracts and salary structures — fully compliant with Peruvian labor law.

What We're Solving

----------------

Payment Periodicity

Out of the box, Odoo Payroll does not include a field to indicate how frequently an employee is paid (weekly, biweekly, monthly, etc.). This module introduces the Payment Period catalog and links it to contracts and salary structures.

Payment Type Classification

Different employees may receive their salary through different payment modalities. The Payment Type catalog lets you classify and report on modalities (bank transfer, cash, etc.) at the contract level.

Special Situations

Labor law in Peru requires tracking employees under special employment situations (e.g., maternity leave, disability, micro-enterprise regime). The Special Situation catalog enables this classification directly on the contract version.

Variable Remuneration

Employees with commission or bonus-based pay require a dedicated classification. The Variable Payment catalog documents and formalizes the variable component of each employee's remuneration scheme.

Setup & User Manual

Step-by-Step Implementation

1. Configure Catalogs

Set up your master data before assigning to contracts:

  • Go to Localización > Localización > Información Plame > [13] Periodicidad de la remuneración and create the periods your company uses (e.g., Monthly, Biweekly).
  • Go to Localización > Localización > Información Plame > [16] Tipo de pago and define payment modalities (e.g., Bank Transfer, Cash).
  • Go to Localización > Localización > Información Plame > [35] Situación especial and create the categories required by regulations.
  • Variable Remuneration has no dedicated catalog menu. Values are assigned directly on the employee contract version.
Tip: All catalogs include a Code, Description, and Abbreviation field. The abbreviation is used as the display name inside contract forms.

2. Assign to Contracts & Structures

How to apply the payment conditions to your employees:

On the Employee Contract

Open the employee's contract (or its active version). You will find the new fields: Payment Period, Payment Type, Special Situation, and Variable Remuneration. Select the appropriate values for each field.

On the Employee Form

HR Managers can also view and edit Special Situation, Payment Type, and Variable Remuneration directly on the employee form via related fields exposed from the active contract version.

On Salary Structures

Salary structures and structure types can also be linked to a Payment Period, allowing the system to know the intended payment frequency for each structure automatically.

Access Control

Payment condition fields on the employee form are protected by the HR Manager group, ensuring sensitive remuneration classification data is only visible to authorized users.

Global Ready | Multi-Language Support

This module is fully translated into English and Spanish (en_US, es_ES, es_PE, es_MX), ensuring a professional experience for international organizations.

QA / User Testing Scenarios

Enterprise Validation Plan

Scenario 1: Payment Period Setup & Contract Assignment

  1. Go to Localización > Localización > Información Plame > [13] Periodicidad de la remuneración.
  2. Create a new period: Code = "MEN", Description = "Monthly", Abbreviation = "MEN".
  3. Open an employee contract and set the Payment Period to "MEN".
  4. Test: The period should be saved and visible on the contract form.

Scenario 2: Special Situation on Employee Form

  1. Log in as HR Manager.
  2. Open an employee's profile and navigate to the HR Settings tab.
  3. Set the Special Situation field to the appropriate value (e.g., Disability).
  4. Test: The value should be saved and should reflect in the underlying contract version record.
  5. Test: Log in as a non-manager user. The field MUST NOT be visible.

Scenario 3: Salary Structure with Periodicity

  1. Go to Payroll > Configuration > Salary Structures (Odoo native menu).
  2. Open a salary structure and set the Payment Period field.
  3. Test: The period should be saved correctly. Repeat for Salary Structure Types.

Scenario 4: Variable Remuneration Assignment

  1. Variable Remuneration has no dedicated catalog menu. Open an employee contract (or its active version) directly.
  2. Set the Variable Remuneration field to the appropriate type.
  3. Result: The field must be saved and the related field on the employee form must reflect the same value.

FAQ & Troubleshooting

Common Resolutions

Fields not visible on the employee form?

Reason: Payment condition fields are restricted to the HR Manager group.

Fix: Log in with a user that belongs to the HR / Manager group to see and edit these fields.

Change on employee form not saving to contract?

Reason: The fields on the employee form are related to the active contract version (hr.version). If there is no active version, the value cannot be stored.

Fix: Make sure the employee has an active contract with a valid contract version before editing payment condition fields.

Module not installing due to missing dependency?

Reason: This module depends on l10n_pe_localization_menu and hr_payroll.

Fix: Ensure both modules are installed before installing Payment Conditions.

Is this compatible with Multi-company?

Answer: Yes!

Detail: Payment condition catalogs are company-agnostic master data. You can define shared catalogs across all companies.
