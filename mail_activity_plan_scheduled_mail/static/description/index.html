Technical Specification for AI & LLM

This Odoo module 'mail_activity_plan_scheduled_mail' turns a mail.activity.type into a scheduled email. It adds the value 'send_mail' to the native category selection of mail.activity.type and reuses the native mail_template_ids field (constrained to exactly one template) plus a send_mail_hour field for the time of day. When such an activity type is scheduled -- typically as one line of a mail.activity.plan launched by the mail.activity.schedule wizard -- the module overrides mail.activity.mixin.activity_schedule to drive the native mail.compose.message and call _action_schedule_message, producing a mail.scheduled.message (the same object the chatter 'Send Later' creates) with a future scheduled_date. The activity id travels in the composer context into send_context (clean_context keeps non default_ keys). When the native cron 'Mail: Post scheduled messages' posts the message on the due date, the overridden mail.scheduled.message _message_created_hook marks the linked activity done via action_feedback (which archives it, active=False, keeping history). No custom cron and no custom outgoing-mail plumbing. Compatible with Odoo 19 Enterprise / Odoo.SH. Multi-language English and Spanish.

Scheduled Email in Plans

Send Later, As One More Activity

Add an email to an Activity Plan and have Odoo send it on its due date automatically -- exactly like the chatter's "Send Later" -- then close the activity by itself when the email goes out.

What We're Solving

----------------

Templates That Never Send

A native activity type can hold an email template, but it only shows manual Preview / Send Now buttons in the chatter. Nothing is ever sent by date. This module makes that template leave automatically on the activity's due date.

No "Plan of Emails" Natively

Activity Plans schedule tasks, not emails. There is no native way to say "queue these emails on these dates". Now an email is just one more line of the plan, configured as an activity type.

Setup & User Manual

Step-by-Step implementation

1. Configuration Guide

Get a scheduled email running in a few steps:

  • Open an Activity Type and set Action to Send Email (scheduled).
  • Pick exactly one email template and the Send At hour.
  • Add that type as a line of an Activity Plan, with its delay.
  • Launch the plan on a record -- the email is queued for its due date.
Note: there is no new cron and no new mail plumbing. The module reuses the very same "Send Later" object and the native queue that already ship with Odoo.

2. Operating Manual (Workflow)

What happens when the plan is launched:

Activity Created

The plan creates the activity exactly as usual, with its responsible and its due date -- it shows in the record's activity list.

Email Queued

The template is rendered through the native composer and stored as a "Send Later" message, scheduled for the due date at your chosen hour.

Sent On The Date

The native cron posts the email when the date arrives, with the full template content, recipients and layout intact.

Activity Auto-Done

The moment the email leaves, the linked activity is marked done (archived) with a note -- no manual click needed.

Visible & Cancelable

Until it goes out, the pending email is a normal "Send Later" message on the record: you can review or cancel it.

Safe By Default

A past due date is clamped to the near future, and only activity types you flag can ever send an email.

FAQ & Troubleshooting

Common Resolutions

The email did not go out on the date?

Reason: the native cron "Mail: Post scheduled messages" is inactive or has not run yet.

Fix: check that scheduled actions are enabled; the email is a standard "Send Later" message and leaves on the next cron pass.

The activity was not marked done?

Reason: "done" archives the activity (active=False); it leaves the open list but its history is kept.

Fix: look at the record's logged "activity done" note; the activity is completed, not deleted.

Does "Send Later" respect the template?

Answer: Yes, fully.

Detail: the template is rendered through the native composer, so subject, body, recipients, attachments and layout are all preserved.

What if the due date is in the past?

Answer: It is handled safely.

Detail: a past instant is clamped to the near future so the send is never rejected.
