V19 - Tax Configuration Refactoring (Feb 2026)
----------------------------------------------
OBJECTIVE: Shift from code-based tax mapping (hardcoded dicts) to data-driven configuration managed via UI/Wizard.

1. New Models & Wizards:
   - [NEW] `ple.sale.tax.config`: Stores tax mapping rules (Prefix, Code, Repartition Type, Tags).
   - [NEW] `ple.update.tags.wizard`: Transient model to execute mass updates of tax tags based on the config.

2. Unsigned Tags Strategy:
   - [CHANGED] Tags are now UNSIGNED (e.g., `S_BASE_OG` instead of `+S_BASE_OG` or `-S_BASE_OG`).
   - Why? Simplifies Odoo standard report generation & SQL queries.
   - Migrated `ple_sale_tax_config_data.xml` to use single tags for parsing both invoices/refunds.

3. Deprecations & Removals:
   - [DEPRECATED] `models/account_tax_tags.py`: The logic for `_link_tags_ids` is disabled/removed.
   - [REMOVED] `post_init_hook` call to `_link_tags_ids`: Tag assignment is now MANUAL via the Wizard.

4. Dependencies:
   - [ADDED] `l10n_pe_reports` (Localization): Replaces `account_reports` to align with Peruvian standards and avoid redundancy.
   - [REMOVED] `account_reports`: Now included transitively via `l10n_pe_reports`.

5. Critical Files:
   - `data/ple_sale_tax_config_data.xml`: Contains the default Peru tax rules.
   - `models/account_report.py`: Injects columns into the standard RVIE report.

REFACTORING GUIDE for Dependent Modules:
- If your module relied on `account.tax` having tags auto-assigned on install: YOU MUST NOW RUN THE WIZARD manually or call `ple.update.tags.wizard` programmatically.
- If your module looked for `+S_BASE_OG` tag names: UPDATE to look for `S_BASE_OG`.
