Technical Specification for AI & LLM

This Odoo 19 module 'portal_navigation_sidebar' adds a persistent navigation sidebar to the customer portal (/my/...) list pages: invoices, sales orders, tickets, projects, addresses and any other portal section. The menu entries are built from the same entries that render the cards of the portal home page (/my), so they follow the installed apps with zero configuration, keep the home page order and grouping by category, and show only the sections that have documents, exactly like the home page. The current section is highlighted. On mobile a button with the current section opens the menu as a side panel, so the list keeps the full screen width. The sidebar is not rendered on the portal home page (the cards are already there), on single document pages (they have their own side panel), nor for anonymous visitors accessing a document through an access-token link. Each user only sees the sections Odoo would show on his own portal home page, so access rights are respected. It can be disabled by archiving the view "Portal Navigation Sidebar" in the backend. Depends only on 'portal'. The collection of entries is isolated in a single function so the module can move to Odoo 20, where the portal home cards become the 'portal.entry' model, by changing that one function. Translated into English and Spanish (es.po).

Portal Navigation

A Persistent Sidebar for the Customer Portal

Let your customers move from Invoices to Orders, Tickets, Projects or Addresses in one click. The menu builds itself from the apps you have installed: nothing to configure.

What We're Solving

----------------

No More Back-and-Forth

In the standard portal, once a customer opens a section (Invoices, Orders, Tickets...) the menu is gone and the only way to reach another section is to go back to the portal home page. This module keeps a menu on the left of every portal list page, so every section is one click away.

Zero Configuration

The options come from the same cards as the portal home page /my, in the same order and grouped by category. Install an app and its section appears; uninstall it and it disappears. There are no menu entries to create or maintain.

Only What Matters

The menu only shows the sections that have documents for the customer: empty ones stay hidden, exactly like on the home page. The section the customer is in is highlighted.

Respects Access Rights

Every user only sees the sections Odoo would show on his own portal home page. Anonymous visitors who open a document through a shared link (access token) do not get the menu at all.

Setup & User Manual

Step-by-Step implementation

1. Configuration Guide

There is nothing to configure. Install it and it works:

  • Go to Apps and search for Portal Navigation Sidebar.
  • Click Install. The only dependency is the standard Portal module.
  • Open any portal list page (e.g. /my/invoices): the menu is already there.
  • To disable: activate the developer mode, go to Settings > Technical > User Interface > Views, search Portal Navigation Sidebar and archive it.
  • To enable again: filter the archived views and unarchive it.
Which sections appear? Exactly the cards of the portal home page /my for that user, in the same order and categories. To change what the menu offers, install or uninstall the apps that add portal sections.

2. Operating Manual (Workflow)

What your customers see in the portal:

Menu on Every List Page

Invoices, Orders, Tickets, Projects, Addresses and every other portal list page show the menu on the left. One click opens any other section.

Same Order & Categories

The options keep the order and the category grouping of the portal home page, so customers find them where they already expect them.

Empty Sections Hidden

Only the sections with documents are listed, like on the home page, and the section being viewed is highlighted.

Mobile Friendly

On a phone a button with the current section opens the menu as a side panel, so lists keep the full screen width.

Out of the Way

It is not shown on the portal home page (the cards are already there) nor on a single document page (an invoice, an order...), which already has its own side panel.

Built for the Next Version

Light and focused: it depends only on Portal, and it is designed to move to Odoo 20 (where the home page cards become the portal.entry model) by changing a single function.

Global Ready | Multi-Language Support

This module is translated into English and Spanish, and the menu shows the same section names your portal home page already shows in the customer's language.

QA / User Testing Scenarios

Enterprise Validation Plan

Scenario 1: Move Between Sections

  1. Log in to the portal as a customer who has at least one invoice and one sales order.
  2. Open /my/invoices.
  3. Test: The menu SHOULD be on the left, with Invoices highlighted.
  4. Click Sales Orders in the menu.
  5. Test: The orders list SHOULD open with the menu still there and Sales Orders now highlighted. No visit to the home page was needed.

Scenario 2: Same Options as the Home Page

  1. As the same customer, open the portal home page /my and note the cards, their order and categories.
  2. Open any list page (e.g. /my/orders).
  3. Test: The menu SHOULD list the same sections, in the same order and categories.
  4. Test: Log in as a customer with no invoices. Invoices SHOULD NOT appear in the menu, just as it does not appear on that customer's home page.

Scenario 3: Where the Menu Is Not Shown

Home page: Open /my. No menu: the cards are already there.

Single document: Open one invoice or order from its list. No menu: the document keeps its own side panel.

Shared link: Share a document, log out and open the link in a private window. No menu for the anonymous visitor.

Scenario 4: Follows the Installed Apps

Goal: Confirm the menu needs no configuration.

  1. Install an app that adds a portal section (e.g. Project) and give the customer access to a project.
  2. Result: Projects SHOULD appear in the menu, in the same place as its card on the home page.
  3. Uninstall the app. Result: The option SHOULD disappear from the menu.

Scenario 5: Mobile & Switch Off

  1. Open /my/invoices on a phone (or narrow the browser window).
  2. Result: Above the list there SHOULD be a button with the current section; tapping it SHOULD open the menu as a panel from the left.
  3. In the backend, archive the view Portal Navigation Sidebar.
  4. Result: Reload the page: the menu SHOULD be gone. Unarchive the view and it SHOULD come back.

FAQ & Troubleshooting

Common Resolutions

A section is missing from the menu?

Reason: The customer has no documents in that section, or no access to it. The menu hides it exactly like the home page does.

Fix: Check the customer's portal home page /my: if the card is not there, the menu will not show it either. Give the customer access to the documents and both will show it.

No menu on the home page or on an invoice?

Reason: This is by design. The home page already shows the cards and a single document page has its own side panel.

Tip: The menu appears on the list pages (/my/invoices, /my/orders...).

A customer opened a link from an email and sees no menu?

Reason: Visitors who open a document through a shared link (access token) without logging in are anonymous, so the menu is not shown.

Fix: The customer logs in to the portal and the menu is there on every list page.

Can I turn it off without uninstalling?

Answer: Yes!

Detail: In developer mode, go to Settings > Technical > User Interface > Views and archive the view Portal Navigation Sidebar. Unarchive it to bring the menu back.
