Technical Specification for AI & LLM

This Odoo module 'account_fix_storno_negative' repairs journal items (account.move.line) that were posted with negative debit or negative credit by Storno (reversal) accounting, which is not allowed in some localizations such as Peru/SUNAT. It adds a server action on account.move bound to the Action menu that opens a confirmation wizard (account.fix.storno.wizard) showing how many lines and moves will be corrected and how many selected entries are ignored (those without negatives). On confirm it re-expresses only the lines where debit < 0 or credit < 0, deriving the standard column from the stored balance (positive debit when balance > 0, positive credit when balance < 0), and clears the sticky is_storno flag on the affected moves. The write is done in SQL to bypass the posted-entry edit lock; because balance, amount_currency, tax lines and reconciliations are untouched, there is no need to reset the entry to draft and the electronic document is not affected. Compatible with Odoo 18 (Enterprise, Odoo.SH, Ganemo Online). Multi-language support for English and Spanish included.

Storno Fixer

Fix Negative Debit & Credit In Bulk

Storno accounting left your journal entries with negative amounts in the debit or credit column? Select the affected entries and re-express them to the standard positive form in one click. No reset to draft, no re-issuing electronic documents.

What We're Solving

----------------

Negative Debit & Credit

When Storno accounting is enabled by mistake, reversals and credit notes post the value as a negative in the natural column instead of a positive on the opposite side. Many localizations (e.g. Peru / SUNAT) do not allow this, breaking legal ledgers and reports.

No Reset To Draft

The fix is purely a presentation change: the stored balance is already correct, so we only move the amount to the right column in positive. Totals, taxes, reconciliations and the electronic document stay untouched — no need to reset posted entries to draft.

Setup & User Manual

Step-by-Step implementation

1. Configuration Guide

This is a temporary utility — install it, run it, uninstall it:

  • First, turn OFF Storno accounting in the company settings so no new negatives are created.
  • Install this module. No configuration is required.
  • A new Action appears on Journal Entries: Fix Storno (negative debit/credit).
  • After the run, simply uninstall the module — it leaves no trace.
Safety first: Always take a backup and test on a staging copy first. The action can be run in batches so you can review results incrementally.

2. Operating Manual (Workflow)

How the correction works for the end-user:

Select The Entries

Open Accounting > Journal Entries, filter the ones with negatives, and select them (bulk selection of thousands of records is supported).

Confirmation Wizard

The wizard shows exactly how many lines and entries will be fixed, and lists how many selected entries are ignored because they have no negatives.

Only Negative Lines

Only journal items where debit or credit is negative are touched. An entry selected by mistake with no negatives is never counted and never modified.

Balance Preserved

The value jumps to the opposite column in positive while the balance stays identical, so reconciliations, taxes and the electronic document are never affected.

Storno Flag Cleared

The sticky is_storno flag is turned off on the fixed entries, so a future recompute never re-paints the negatives.

FAQ & Troubleshooting

Common Resolutions

Why do I have negative debit/credit?

Reason: Storno accounting was enabled, so reversals posted the amount as a negative in the natural column.

Fix: Turn off Storno accounting, then select the affected entries and run Fix Storno.

Do I need to reset entries to draft?

No. Only the debit/credit representation is corrected; the balance is unchanged.

Detail: The write is done at database level on the posted entries, so nothing is re-opened or re-issued.

Will it change my electronic invoice or taxes?

Reason: The electronic document and tax lines are built from the invoice totals, not from the internal debit/credit split.

Answer: No. Totals, taxes and the electronic document are untouched.

What if I select an entry with no negatives?

Answer: It is safely ignored.

Detail: The wizard filters line by line, so a healthy entry is never counted and never modified.
