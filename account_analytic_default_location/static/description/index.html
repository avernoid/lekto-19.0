Account Analytic
Default Location

Automate your analytic accounting by mapping warehouse locations to analytic accounts. Ensure precise cost tracking for every inventory movement without manual data entry.

The Problem

In multi-warehouse environments, standard Odoo rules often fail to allocate costs precisely. Companies struggle to distinguish costs between the same product moving through different branches or specific stock locations, leading to manual journal adjustments and reporting errors.

The Solution

This module introduces granularity to your Analytic Distribution Models. You can now define rules based on: Origin Warehouse, Origin Location, Destination Location, Salesperson (Invoice), and Journal (Invoice). Odoo automatically applies the correct analytic account to every stock move, ensuring 100% accurate cost allocation.

Key Features

Why this module is essential for your accounting

Odoo 19 Merging Logic

Rules for different analytic plans now merge automatically, allowing multiple dimensions on a single line.

Multi-Prefix Support

Use comma-separated account prefixes (e.g., '40, 60, 64') in a single rule for maximum flexibility.

Supreme Priority & Protection

Analytic accounts from SO/PO are respected, and manual user entries are never overwritten.

Dimensions Included

Logistics

Warehouse, Source Location, Destination Location. Applied on Invoices, SO, and stock movements.

Salesperson

Matches Invoice Salesperson. Built-in warnings clarify scope versus Sales Orders.

Journal

Filter by Accounting Journal to differentiate analytic distribution for Receipts vs Bills.

Module Name: Account Analytic Default Location (Odoo 19 Ready)
Technical Name: account_analytic_default_location
Category: Accounting / Logistics
Functionality: Extends account.analytic.distribution.model to support origin_warehouse_id, origin_location_id, dest_location_id, invoice_user_id, and journal_id. Implements the native Odoo 19 merging logic, allowing distributions from multiple matching models to combine if they target different plan roots. Advanced Matching: Supports comma-separated account_prefix (e.g., '40, 60, 64') with manual prefix-matching logic for robust account branch allocation. Priority System: Uses "Supreme Priority" to respect distributions coming from Sales/Purchase Orders and "Override Protection" for manual user changes.
