Technical Specification for AI & LLM

This Odoo module 'custom_work_order' adds a QWeb PDF report named "Orden de Trabajo" (Work Order) to the stock.picking model. It reuses the corporate branding (header, footer and paper format) defined in the sale_corporate_quotation module. The report renders a fixed document code (PR-VE-FT-012 Rev. 0), general data (creation date, contractual delivery date, customer, RUC, purchase order, project), Part 1 - product description table (item, product, source location, quantity and weight with a total weight row), Part 2 - observations (work_order_observations field from sale_custom_fields), and Part 3 - shipping details (delivery address, delivery contact and notes). It adds a single new field delivery_contact_name on res.partner and a "Print Work Order" button on the stock picking form. Depends on stock, sale_stock, sale_corporate_quotation and sale_custom_fields. Compatible with Odoo 19 (Enterprise, Odoo.SH, Ganemo Online). Multi-language support for English and Spanish included.

What We're Solving

----------------

One-Click Work Order

Stop building Work Orders by hand. A "Print Work Order" button right on the delivery form produces a ready-to-sign PDF ("Orden de Trabajo") pulling every value from the picking and its sales order.

Consistent Branding

The report reuses the header, footer and paper format of your corporate quotation. Logos, RUC, address, document code and the company slogan stay identical across every document you send.

Setup & User Manual

Step-by-Step implementation

1. Configuration Guide

Get a corporate Work Order in 4 simple steps:

  • Install the module (it pulls in Sales, Inventory and the corporate quotation branding automatically).
  • Make sure your company logo, RUC, address and phone are set in Settings > Companies.
  • On delivery contacts, fill the Delivery Contact field (name of who receives the goods).
  • Add any free text in the Sales Order Work Order Observations field.
Smart Explainer: The Work Order number is built automatically as Sales Order - Picking (e.g. S00021 - WH/OUT/00010), so it always ties the document back to its origin.

2. Operating Manual (Workflow)

What ends up on the printed Work Order:

General Data

Creation date, contractual delivery date, customer, RUC, customer purchase order (OC) and project reference — all pulled from the picking and its sales order.

Part 1 — Products

Item number, product and line description, source location, quantity and weight per line, plus an automatic Total Work Order Weight row.

Smart Locations

Reserved stock shows its real source location. Not yet reserved? The report intelligently prints Manufacturing, Purchase or Pending based on the move origin.

Part 3 — Shipping

Delivery place, address, contact information (name + phone) and notes, taken from the order's shipping address — ready for the person who picks up or receives the goods.

Part 2 — Observations

A free-text Observations block fed by the Work Order Observations field on the sales order, for special handling or production notes.

Corporate Layout

Repeating corporate header (logos, RUC, address, document code, page numbers) and footer slogan on every page, matching your quotation paper format exactly.

QA / User Testing Scenarios

Enterprise Validation Plan

Scenario 1: Print from a Picking

  1. Confirm a Sales Order with storable products and open its Delivery (picking).
  2. Click the "Print Work Order" button in the picking header.
  3. Test: A PDF "Orden de Trabajo" is generated with the corporate header and footer.
  4. Test: The Work Order number reads Sales Order - Picking.

Scenario 2: Products & Total Weight

  1. Set a weight on the products of the order.
  2. Print the Work Order.
  3. Test: Part 1 lists each product with quantity and line weight.
  4. Test: The Total Work Order Weight row equals the sum of all line weights.

Scenario 3: Smart Source Location

Reserved: Reserve stock — the real source location is shown.

Not reserved: Depending on the move origin, the report prints:

  • Made-to-order from manufacturing -> Manufacturing.
  • Made-to-order from a vendor -> Purchase.
  • No origin yet -> Pending.

Scenario 4: Delivery Details

  1. On the order's delivery address, fill the Delivery Contact field and a phone number.
  2. Print the Work Order.
  3. Result: Part 3 shows the delivery place, address, contact (name + phone) and notes.

Scenario 5: Observations

  1. Open the Sales Order and type text in Work Order Observations.
  2. Print the Work Order from the related picking.
  3. Result: Part 2 shows exactly that text; if empty, it shows "-".

FAQ & Troubleshooting

Common Resolutions

The header has no logo or RUC?

Reason: The report reads this data from the company record.

Fix: Set the company logo, RUC (VAT), address and phone in Settings > Companies.

Customer, OC or Project shows "-"?

Reason: These come from the linked Sales Order.

Fix: Print from a picking created from a Sales Order, and fill the Purchase Order and Customer Reference (Project) fields on it.

Where is the "Print Work Order" button?

Reason: It lives on the stock picking form.

Fix: Open any Delivery / Receipt (Inventory > Operations); the button is in the header next to Validate. It is also available from the print menu.

Does it work for any picking type?

Answer: Yes!

Detail: The report is bound to stock.picking, so it works on deliveries, receipts and internal transfers. Sales-related fields simply show "-" when there is no sales order.
