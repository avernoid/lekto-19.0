Technical Specification for AI & LLM

This Odoo module 'sale_project_auto_create' creates a project from a sales order on confirmation by policy, decoupled from the catalogue, so you do not need to add a service product line whose service_tracking is configured to generate a project. The trigger is a boolean on sale.order ('auto_create_project', shown in the Other Info tab) whose default is computed from a boolean on crm.team ('auto_create_project'). On _action_confirm, before calling super(), eligible orders create a project.project linked to the order via reinvoiced_sale_order_id, with its analytic account from sale.order._prepare_analytic_account_data(); project.project.create() then wires order.project_id automatically. Because it runs before super(), the stock procurement carries project_id like the native service-product flow. It never collides with the native sale_project generation: eligibility defers to the native helpers _get_so_lines_new_project and _get_so_lines_task_global_project and skips when order.project_id is already set, so no duplicate project is created and re-confirmation is idempotent. Depends on sale_project. Compatible with Odoo 19 (Enterprise, Odoo.SH, Ganemo Online). Multi-language support for English and Spanish included.

Sale Project Auto Create

One Project per Sales Order, No Product Line Needed

Natively, Odoo only creates a project when the order carries a service product configured for it — a line that shows on the quotation even at price 0. This module creates the project by policy on confirmation, with its analytic account, and never gets in the way of the native flow.

What We're Solving

----------------

The Dummy Service Line

To get a project per order natively, you must add a service product set to "Project". Even at price 0 it still appears on the quotation, cluttering the document when all you want is to control one project per sales order.

Project by Policy

Flag a sales team (or a single order) and the project is created on confirmation, with its analytic account assigned to the order — exactly the native result, but without any product line.

Setup & User Manual

Flag a team, confirm an order

1. Configuration Guide

Enable the policy in 2 simple steps:

  • Go to CRM / Sales > Configuration > Sales Teams.
  • Open a team and tick "Create Project on Sales Confirmation".
  • New orders of that team inherit the policy automatically.
  • Override it per order in the Other Info tab.
Smart Explainer: The order toggle lives in Other Info on purpose — it keeps your quotation header clean while still letting you decide order by order.

2. Operating Manual (Workflow)

How the system behaves for the end-user:

Confirm the Order

On confirmation, an eligible order creates its project and links it — no extra clicks, no wizard.

Analytic Account Set

The project's analytic account is assigned to the order, so invoices and costs flow to the project like the native path.

Stock Gets the Project

It runs before native confirmation, so delivery procurement carries the project, exactly like Odoo's service-product flow.

Never Duplicates

If a service product already creates a project, this module steps aside — one project per order, re-confirmation safe.

QA / User Testing Scenarios

Enterprise Validation Plan

  1. Flag a sales team with "Create Project on Sales Confirmation".
  2. Create an order on that team with only regular products and confirm.
  3. Result: a project is created and linked to the order, with its analytic account — no service line required.

  2. Result: confirming the order creates no project.

FAQ & Troubleshooting

Common Resolutions

Do I still need a service product?

Answer: No.

Fix: the project is created from the team/order policy, so your quotation stays free of dummy service lines.

Will it clash with the native flow?

Answer: No.

Detail: when a service product already generates a project, the module does nothing — one project per order is always respected.

Can I decide order by order?

Answer: Yes.

Detail: the team sets the default; the toggle in the order's Other Info tab overrides it.

Does the project get an analytic account?

Answer: Yes!

Detail: the project is created with its analytic account and the account is assigned to the order, so invoices and costs flow to the project.
