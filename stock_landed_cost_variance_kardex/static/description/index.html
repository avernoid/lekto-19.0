Technical Specification for AI & LLM

This Odoo module 'stock_landed_cost_variance_kardex' is an auto_install bridge between 'stock_move_kardex_qty' (which owns the Kardex columns on stock.move and depends on stock_account only) and 'stock_landed_cost_variance' (which owns the stock.value.variance model and needs stock_landed_costs). It implements the hook _kardex_variance_amounts() and re-declares the @api.depends of _compute_kardex_variance on variance_line_ids, so kardex_value stays net of live variances and kardex_value_adjustment and kardex_adjusted_qty are populated. Absorbed variance rows contribute zero, so a valuation recalculation and a variance are never counted twice. Without this bridge the Kardex columns behave exactly as they did before. Compatible with Odoo 19 (Enterprise, Odoo.SH, Ganemo Online). Multi-language support for English and Spanish included.

Variance Bridge

Value Variances Into The Kardex Columns

A two-file bridge with a single job: make the movement-level Kardex columns state what each movement is really worth once a late landed cost or vendor bill has been recorded. It installs itself when both sides are present, and needs no configuration at all.

What We're Solving

----------------

Two Modules, No Forced Dependency

The Kardex columns depend on stock accounting alone, on purpose. The variance model needs Landed Costs. Rather than forcing that on every install of the columns, the columns read a hook that returns nothing by default — and this bridge supplies the real source.

Columns That Stay Fresh

A stored column is only as good as the dependencies that recompute it. The bridge re-declares those dependencies now that the real source exists, so editing a variance updates the ledger immediately instead of leaving a stale number behind.

Setup & User Manual

Step-by-Step implementation

1. Configuration Guide

There is nothing to configure. There is nothing to switch on.

  • Install Kardex Quantities & Value.
  • Install Stock Value Variance.
  • This bridge installs by itself.
  • Show Kardex Adjustment and Adjusted Qty from the optional columns of the Moves Analysis list.
Inert by construction: uninstall it and the Kardex columns behave exactly as they did before. It adds no field, no menu and no view of its own — it extends the existing list with two optional columns.

2. Operating Manual (Workflow)

What the three columns say, once the bridge is in place:

Kardex Value, Net

The signed value of the movement plus the corrections carried by the variances that are still live. One column, one number, no mental arithmetic.

Kardex Adjustment

The correction on its own, so the difference between the native Value and what the ledger counts is always explainable without opening anything.

Adjusted Qty

How much had already left the warehouse when the movement was last revalued. Informative only — no unit moved, so it deliberately does not add up in subtotals.

Never Counted Twice

A variance already folded into the movement values by a valuation recalculation contributes zero. Correcting the same money twice is the classic failure of this kind of column, and it is ruled out by construction.

Signs Handled Once

Each variance row carries its ledger effect already signed, so nothing downstream has to know that an incoming movement gives the amount back one way and an outgoing one the other.

Reuses The Native List

The columns land in the standard Moves Analysis list, hidden by default. Native filtering, grouping and exporting keep working exactly as they do today.

FAQ & Troubleshooting

Common Resolutions

Do I need to install this one?

No. It installs itself as soon as both sides are present, and it is useless on its own.

Fix: if it is not installed, check that both Kardex Quantities & Value and Stock Value Variance really are.

The adjustment column is empty. Why?

Reason: nothing has recorded a variance for that movement — or every variance on it is flagged Absorbed.

Fix: open the movement's value variances and check the Absorbed flag before suspecting the column.

Does it change valuation or accounting?

No. It only feeds presentation columns.

Detail: no stock move, no journal entry, no value rewritten. The journal entry, if you want one, belongs to Stock Value Variance.

I wrote directly in SQL. Now what?

Answer: recompute the columns.

Detail: the Kardex columns are stored computed fields. Any SQL write on value, is_in, is_out or state leaves them stale — with or without this bridge. Recompute them through the ORM before committing.
